# RAFT Core Implementation - Debugging Guide for Team 3

## Quick Troubleshooting

### Problem: No Leader Elected After 2 Seconds

**Symptoms:**
```
Initial state: all nodes are FOLLOWER
After 2 seconds: still no LEADER
No election activity in logs
```

**Causes to Check:**

1. **Election timers not running**
   ```javascript
   // Check: Is raftCore.start() called?
   raftCore.start();  // Must call this!
   
   // Verify timer service
   console.log(raftCore.timerService.electionTimer);  // Should not be null
   ```

2. **RequestVote RPC not being sent**
   ```javascript
   // In your election loop, you should be sending RequestVote
   const voteRequest = raftCore.prepareRequestVote();
   
   for (let nodeId of raftCore.otherNodeIds) {
     // Send HTTP POST /request-vote to each node
     axios.post(`http://node-${nodeId}:5001/request-vote`, voteRequest);
   }
   ```

3. **Network communication failing silently**
   ```javascript
   // Verify other replicas' /request-vote endpoint exists
   curl http://localhost:5002/request-vote
   // Should get: METHOD NOT ALLOWED (no GET)
   
   // Test with POST
   curl -X POST http://localhost:5002/request-vote -d '{}' \
     -H 'Content-Type: application/json'
   // Should get response JSON
   ```

4. **Vote response not being processed**
   ```javascript
   // After receiving vote response, must call:
   raftCore.recordVoteResponse(voteGranted);
   
   // Check if majority is reached
   console.log('Votes received:', raftCore.election.votesReceived);
   console.log('Has majority:', raftCore.election.hasMajority());
   ```

5. **Wrong quorum size**
   ```javascript
   // For 3 nodes, quorum = 2
   // Check: QUORUM_SIZE in constants.js
   const QUORUM = require('./replica-core/constants').QUORUM_SIZE;
   console.log('Quorum:', QUORUM);  // Should be 2
   ```

**Debug Script:**
```javascript
const RaftCore = require('./replica-core');

const node1 = new RaftCore('node1', ['node2', 'node3']);
node1.start();

// Monitor election state
setInterval(() => {
  console.log({
    state: node1.getState(),
    term: node1.getTerm(),
    votes: node1.election.votesReceived,
    hasMajority: node1.election.hasMajority(),
    timerRunning: node1.timerService.electionTimer !== null
  });
}, 100);

// Timeout
setTimeout(() => {
  console.error('No leader after 3 seconds!');
  process.exit(1);
}, 3000);
```

### Problem: Leader Elected But Strokes Don't Replicate

**Symptoms:**
```
✓ Leader elected successfully
✓ Client sends stroke to leader
✓ Entry appended to leader's log
✗ Followers don't receive the stroke
✗ commitIndex stuck at -1
```

**Causes to Check:**

1. **Not sending AppendEntries**
   ```javascript
   // You need a heartbeat loop (leader only)
   setInterval(() => {
     if (!raftCore.isLeader()) return;
     
     // For each follower, prepare and send AppendEntries
     for (let followerId of raftCore.otherNodeIds) {
       const ae = raftCore.prepareAppendEntries(followerId);
       // Send as HTTP POST /append-entries to that replica
     }
   }, 150);  // Every 150ms
   ```

2. **AppendEntries endpoint not implemented**
   ```javascript
   // Your replica server must have:
   app.post('/append-entries', (req, res) => {
     const result = raftCore.handleAppendEntries(req.body);
     res.json(result);
   });
   ```

3. **Wrong AppendEntries format**
   ```javascript
   // The request must have this exact format:
   {
     term: 10,
     leaderId: 'replica1',
     prevLogIndex: 5,
     prevLogTerm: 9,
     entries: [
       { index: 6, term: 10, type: 'stroke', data: {...} }
     ],
     leaderCommitIndex: 5
   }
   
   // Generated by:
   const ae = raftCore.prepareAppendEntries(followerId);
   // Don't modify the format!
   ```

4. **Not handling replication responses**
   ```javascript
   // After receiving response from appendEntries RPC:
   if (response.success) {
     raftCore.handleReplicationSuccess(followerId, response.lastLogIndex);
   } else {
     raftCore.handleReplicationFailure(followerId, response.conflictIndex);
   }
   
   // This updates matchIndex/nextIndex for commit advancement
   ```

5. **Log mismatch happening**
   ```javascript
   // When response.success = false:
   {
     success: false,
     term: 10,
     conflictIndex: 4,  // This tells you where to backoff
     lastLogIndex: 5
   }
   
   // Then on next heartbeat:
   // prepareAppendEntries will use lower nextIndex
   // Try again with earlier entries
   ```

**Debug Script:**
```javascript
// In your heartbeat loop, add logging:
let replicationAttempts = 0;
let replicationSuccesses = 0;

if (raftCore.isLeader()) {
  setInterval(() => {
    for (let followerId of raftCore.otherNodeIds) {
      const ae = raftCore.prepareAppendEntries(followerId);
      
      axios.post(`http://replica-${followerId}:5001/append-entries`, ae)
        .then(response => {
          replicationAttempts++;
          if (response.data.success) {
            replicationSuccesses++;
            raftCore.handleReplicationSuccess(followerId, response.data.lastLogIndex);
          } else {
            console.log('Replication failed for', followerId);
            console.log('  Conflict index:', response.data.conflictIndex);
            raftCore.handleReplicationFailure(followerId, response.data.conflictIndex);
          }
        })
        .catch(err => {
          console.error('RPC failed to', followerId, err.message);
        });
    }
    
    // Log progress
    console.log({
      leaderState: raftCore.getNodeInfo(),
      replicationAttempts,
      replicationRate: (replicationSuccesses / replicationAttempts * 100).toFixed(1) + '%',
      nextIndices: raftCore.nodeState.nextIndex,
      matchIndices: raftCore.nodeState.matchIndex
    });
  }, 500);
}
```

### Problem: Node Doesn't Rejoin After Restart

**Symptoms:**
```
✓ Node running fine
✓ Stop node (SIGTERM, crash simulation)
✓ Restart node
✗ Node won't rejoin cluster
✗ Followers don't sync from leader
✗ New node starts with empty log
```

**Causes to Check:**

1. **State not persisted before shutdown**
   ```javascript
   // Must persist BEFORE shutting down
   const state = raftCore.getPersistentState();
   fs.writeFileSync('state.json', JSON.stringify(state));
   
   // Then process.exit()
   
   // On startup, BEFORE calling raftCore.start():
   const saved = JSON.parse(fs.readFileSync('state.json'));
   raftCore.restoreState(saved);
   raftCore.start();
   ```

2. **SyncLog endpoint not implemented**
   ```javascript
   // Restarted node will request sync via:
   POST /sync-log
   { followerId: 'replica2', fromIndex: 0 }
   
   // Your endpoint:
   app.post('/sync-log', (req, res) => {
     const result = raftCore.handleSyncLog(
       req.body.followerId,
       req.body.fromIndex
     );
     res.json(result);
   });
   ```

3. **SyncLog request not being sent**
   ```javascript
   // After AppendEntries fails:
   const response = raftCore.handleAppendEntries(ae);
   
   if (!response.success) {
     // Check if out of sync:
     const syncReq = raftCore.checkAndRequestSync(
       ae.leaderId,
       ae.prevLogIndex,
       ae.prevLogTerm
     );
     
     if (syncReq) {
       // Send SyncLog request!
       axios.post(`http://leader:5001/sync-log`, syncReq);
     }
   }
   ```

4. **Not applying synced entries**
   ```javascript
   // After receiving SyncLog response:
   const response = await axios.post(
     `http://leader:5001/sync-log`,
     { followerId: nodeId, fromIndex }
   );
   
   // Must apply the response:
   raftCore.applySyncLogResponse(
     leaderId,
     response.data.entries,
     response.data.commitIndex
   );
   
   // This appends entries and updates commitIndex
   ```

5. **Entries not being persisted regularly**
   ```javascript
   // Persist periodically, not just on shutdown
   setInterval(() => {
     const state = raftCore.getPersistentState();
     fs.writeFileSync('state.json', JSON.stringify(state));
   }, 5000);  // Every 5 seconds
   ```

**Debug Script:**
```javascript
// Test persistence & recovery
const RaftCore = require('./replica-core');
const fs = require('fs');

console.log('=== Creating node ===');
const node = new RaftCore('node1', ['node2', 'node3']);
node.start();

// Add some entries
setTimeout(() => {
  node.handleAppendEntries({
    term: 1,
    leaderId: 'leader',
    prevLogIndex: -1,
    prevLogTerm: 0,
    entries: [
      { index: 0, term: 1, type: 'stroke', data: { x: 10 } },
      { index: 1, term: 1, type: 'stroke', data: { x: 20 } }
    ],
    leaderCommitIndex: 1
  });
  
  console.log('Log length before:', node.nodeState.log.length);
  
  // Save state
  const state = node.getPersistentState();
  fs.writeFileSync('test-state.json', JSON.stringify(state));
  console.log('State saved');
  
  // Simulate shutdown
  node.stop();
  console.log('Node stopped');
  
  // Simulate restart
  setTimeout(() => {
    console.log('\n=== Restarting node ===');
    const node2 = new RaftCore('node1', ['node2', 'node3']);
    
    // Restore before starting
    const saved = JSON.parse(fs.readFileSync('test-state.json'));
    node2.restoreState(saved);
    
    console.log('State restored');
    console.log('Log length after:', node2.nodeState.log.length);
    
    if (node2.nodeState.log.length === 2) {
      console.log('✓ Persistence works!');
    } else {
      console.error('✗ Persistence failed!');
    }
  }, 100);
}, 100);
```

### Problem: Strokes Commit on Leader But Don't Apply on Followers

**Symptoms:**
```
✓ Leader appends stroke
✓ Leader replicates to followers
✓ Followers acknowledge
✓ Leader advances commitIndex
✗ Followers' commitIndex doesn't advance
✗ Stroke isn't applied on followers
```

**Causes to Check:**

1. **Not updating commitIndex on followers**
   ```javascript
   // When follower receives AppendEntries:
   const response = raftCore.handleAppendEntries(appendEntries);
   
   // handleAppendEntries updates commitIndex internally!
   // Check the leaderCommitIndex field in request:
   {
     leaderCommitIndex: 42  // This tells followers to advance
   }
   ```

2. **Leader not updating leaderCommitIndex in heartbeats**
   ```javascript
   // When preparing AppendEntries:
   const ae = raftCore.prepareAppendEntries(followerId);
   
   // This includes: leaderCommitIndex: raftCore.nodeState.commitIndex
   // Make sure this value is correct!
   ```

3. **onEntryCommitted callback not registered**
   ```javascript
   // You MUST register this callback:
   raftCore.onEntryCommitted((entry) => {
     console.log('Entry committed:', entry.index);
     // Apply to state machine
     canvas.drawStroke(entry.data);
   });
   
   // Without this, committed entries won't be applied
   ```

4. **Entries not being applied in order**
   ```javascript
   // Entries must be applied in index order
   // onEntryCommitted is called once per committed entry
   // Process them in order:
   
   raftCore.onEntryCommitted((entry) => {
     // entry.index tells you the position
     // Must process all indices 0, 1, 2, 3, ...
     // Not out of order!
     applyEntry(entry);
   });
   ```

**Debug Script:**
```javascript
const RaftCore = require('./replica-core');

// Setup 3 nodes
const node1 = new RaftCore('node1', ['node2', 'node3']);
const node2 = new RaftCore('node2', ['node1', 'node3']);
const node3 = new RaftCore('node3', ['node1', 'node2']);

// Track commits
const commits = {
  node1: [],
  node2: [],
  node3: []
};

[node1, node2, node3].forEach(node => {
  node.onEntryCommitted((entry) => {
    commits[node.nodeId].push(entry.index);
    console.log(`${node.nodeId}: Committed entry ${entry.index}`);
  });
});

// Start all
[node1, node2, node3].forEach(n => n.start());

setTimeout(() => {
  // Simulate leader election (node1 wins)
  node1.nodeState.currentTerm = 1;
  node1.stateMachine.becomeLeader(1);
  
  // Client request on leader
  node1.clientRequest('stroke', { x: 10 });
  
  // Simulate replication
  [node2, node3].forEach(node => {
    const response = node.handleAppendEntries(
      node1.prepareAppendEntries(node.nodeId)
    );
  });
  
  // Advance commitIndex
  node1.logReplication.advanceCommitIndex(['node2', 'node3']);
  
  // Check if all nodes committed
  setTimeout(() => {
    console.log('\nCommitted indices:');
    console.log('  node1:', commits.node1);
    console.log('  node2:', commits.node2);
    console.log('  node3:', commits.node3);
    
    if (JSON.stringify(commits.node1) === JSON.stringify(commits.node2) &&
        JSON.stringify(commits.node1) === JSON.stringify(commits.node3)) {
      console.log('\n✓ All nodes committed same entries!');
    } else {
      console.error('\n✗ Commit mismatch!');
    }
  }, 100);
}, 1000);
```

## General Debugging Checklist

### Before Running System:

- [ ] All 3 replica servers start without errors
- [ ] Can curl each /health endpoint
- [ ] RAFT core initializes with correct node IDs
- [ ] Callbacks are registered
- [ ] State persistence directory exists and is writable

### During System Startup:

- [ ] All nodes start as FOLLOWER
- [ ] Election timeouts are randomized (500-800ms)
- [ ] Within 1 second, one node becomes LEADER
- [ ] Other 2 nodes stay as FOLLOWER
- [ ] Leader sends heartbeats (log messages every 150ms)

### During Normal Operation:

- [ ] Clients can send strokes to Gateway
- [ ] Gateway forwards to current leader
- [ ] Leader appends to log (check endpoints response: { success, index })
- [ ] Followers receive AppendEntries
- [ ] All nodes have same log length after replication
- [ ] Entries are committed when majority acks
- [ ] Committed entries trigger onEntryCommitted callback
- [ ] Gateway broadcasts to all clients

### During Failover:

- [ ] Kill leader process
- [ ] Remaining 2 nodes detect failure (election timeout ~800ms)
- [ ] One of them becomes new leader
- [ ] New leader has higher term number
- [ ] New strokes go to new leader
- [ ] Old clients reconnect (Gateway detects change)

### During Recovery:

- [ ] Restarted node loads persisted state
- [ ] Out-of-sync detected (AppendEntries fails)
- [ ] SyncLog request sent
- [ ] Leader responds with committed entries
- [ ] Node catches up and participates normally
- [ ] No duplicate strokes

**Remember:** The RAFT Core is already implemented and tested. Your job is to connect it properly, send RPCs to the right places, and handle responses correctly.

If something isn't working, 90% of the time it's one of:
1. Not calling raftCore method or method not being called
2. Wrong RPC format
3. RPC not being sent/received
4. Callback not registered
5. State not being persisted/restored

Use the debug scripts above to isolate the issue!
